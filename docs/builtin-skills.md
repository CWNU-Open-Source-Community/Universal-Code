# 内置技能 / Built-in skills

本页对应内置 Registry 的十四项当前版本。历史 `archives/` 为恢复精确版本保留，不重复计数。安装的外部技能、工具、MCP、全局提示词和任务完成状态也不属于这个数量。

## 按任务选择

| 工作 | 技能 | 作用 |
| --- | --- | --- |
| 编程 | `code` | 沿实际入口读代码、保留用户修改、按工具合同编辑并核对写入结果 |
| 前端视觉 | `frontend-design` | 视觉层级、字体与间距、紧凑度、响应式、交互状态、SVG/CSS 动画和渲染检查 |
| 运行验收 | `run-verify` | 找到实际启动路径，运行程序或页面，以操作和观察验证结果 |
| 定向检查 | `focused-checks` | 按差异与风险选测试、构建、恢复和文档检查 |
| 故障诊断 | `debug`、`doctor` | 故障证据与分层定位；`doctor` 仅在 Plan 做只读诊断 |
| 审查 | `review`、`security-review` | 代码、生命周期与测试证据审查；信任边界和安全问题审查 |
| 简化 | `simplify` | 验证之后清理冗余、重复和不必要的抽象 |
| 学习和脚本 | `learn`、`script` | 分步解释与核实；有界脚本任务 |
| 显式工作流 | `plan-delivery`、`loop-monitor`、`run-skill-generator` | 操作者明确选择的交付、监测或候选技能生成流程 |

三项显式工作流不会出现在模型的自主读取目录中。其余十一项仍按当前 Profile、Surface、Phase 和接收角色过滤，不会全部发送。例如 Code/Deliver/root 当前有八项可发现，Plan-only 的 `doctor` 和其他 Profile 的 `learn`、`script` 不在其中。

`plan-delivery@1.3.0` 按任务提出一至三个方向，清楚且有界的小任务优先一个，只有实质取舍才增加备选；等待操作者确认实际提出的方向及其人工验收模式。已有 Run 固定的 `1.2.0` 仍从归档按原始版本、哈希和字节恢复。

`code` 负责整体编程流程；视觉决策交给 `frontend-design`；真实程序验证使用 `run-verify`；测试范围选择交给 `focused-checks`。不需要为一个任务读取全部技能。当前 `frontend-design` 只支持 Code Profile / Code Surface / Plan 或 Deliver / root。

## 普通对话怎样使用

共享 Supervisor 在实际模型工具目录中提供 `skill_read`，描述列出当前兼容技能的用途、精确版本和正文摘要。模型可以自行读取相关技能，用户无需先执行 CLI 选择命令。操作者既有的显式选择仍有效，同名固定版本优先。

成功读取后，Go 在后续 root 请求中从二进制内嵌的精确版本重新组装正文，经过压缩或同一 Run 重启也能恢复。工具 stdout、历史文本和模型摘要不能充当技能正文的权威来源。读取不会修改操作者的选择，也不会授予文件、命令、浏览器、网络或审批权限。

已启用的安装技能通过同一 `skill_read` 读取主 `SKILL.md` 时，Go 会按当前安装、版本、启用代次、调用策略和运行模式复核成功收据，并在本轮系统消息中绑定仍实际存在的原生调用与结果。只有绑定的主正文 `content` 可提供低优先级流程建议，服从系统、当前用户与适用的项目规则；资源文件保持普通数据。结果中的 `workflow_guidance` 字段仅描述用途，复制同样的 JSON、标记或历史输出不能建立绑定。压缩移除正文后仅恢复精确引用，需要时重新读取；停用或切换版本会撤销旧绑定。

读取记录保存在已有工具账本中，明确标记模型来源。失败、pending 或取消且未提交的读取不激活技能。当前及历史固定版本都必须满足调用和模式约束。外部包的安装、选择及其不可信指导规则保持独立。

内置上下文沿用至多八项、8192 字节保守 token 上界的共享限制，含操作者固定集合；这是技能上下文限制，不是单次文件编辑或模型输出限制。超限显式返回错误。技能正文源哈希与脱敏后交付哈希分别保存，不能混用。

## 前端视觉技能包含什么

- 先理解用户参考、现有页面与主要操作，再决定层级、密度、色彩、排版和留白。
- 把队列、状态和次要操作保持紧凑；按需展开详情，检查长文字与窄屏。
- 实现真实控件行为、键盘焦点、错误和空状态；错误后保留输入。
- 分清内联 SVG 与外部图片的 CSS 作用范围，验证预期部件运动，尊重减少动态效果。
- 在工具支持时查看实际渲染图，再操作页面。截图成功、看过截图和交互通过分别陈述。

## 验证边界（2026-09-30）

定向集成测试覆盖真实 HTTP 请求形状、相同 Run 多执行段和压缩后恢复、SQLite 重开、取消窗口、pending 恢复、预算与旧数据迁移。

一次生产 Web UI + DeepSeek v4 flash 的真实任务自行读取了 `code@1.3.0` 和 `frontend-design@1.0.0`，精确正文进入后续 root 请求，真实压缩之后仍保留。该任务只完成页面导航和状态查询，创建了两个已自动授权的文件提案，但没有 `workspace_apply`、截图或交互检查；两次未执行工具的 continue 答复未通过现有生命周期校验，Run 暂停。**因此已验证发现与投递，尚未验证独立完成前端作品及视觉验收，也没有对照实验能量化质量提升。** `run-verify@1.2.0` 在这次任务中没有被读取。

排查时依次查看目录、`skill_read` 成功收据、真实 provider 请求和作品检查工具记录；数量或模型口头完成不能替代这些证据。实现边界见 [ADR 0160](adr/0160-model-readable-builtin-skills.md)。
